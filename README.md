# Smart Traffic Management System

A data analytics pipeline for traffic monitoring. It simulates IoT-style sensor data across several intersections, classifies congestion states with machine learning, and recommends adaptive signal timing, with a Streamlit dashboard.

> **Simulated data.** All sensor readings are generated by `src/data_generator.py`. No real traffic data or field deployment is involved.

---

## Problem Statement

Fixed-cycle traffic signals don't adapt when traffic changes during the day. This project builds a data pipeline that classifies the congestion state at each intersection and suggests a signal timing for that state, as a starting point for adaptive control.

---

## Solution Overview

| Component | Details |
|---|---|
| Data Simulation | IoT sensor data generator — vehicle count, speed, density across 5 intersections, 7 days |
| Feature Engineering | Cyclical time encoding, rush-hour flags, rolling averages |
| Classification | Random Forest classifier predicting traffic state (Free Flow / Moderate / Congested / Critical) |
| Optimization | Rule-based adaptive signal timing engine |
| Dashboard | Streamlit app for real-time monitoring and timing recommendations |

---

## Dataset

- **Type:** simulated. `src/data_generator.py` produces 3,360 readings: 5 intersections, every 15 minutes, over 7 days, with vehicle count, average speed and density, including rush-hour peaks and quiet nights.
- **Labels:** the four traffic states (Free Flow, Moderate, Congested, Critical) are assigned by rules on vehicle count and speed.
- Saved as `data/simulated_traffic_data.csv`.

## Architecture

```
data_generator.py -> preprocess.py (time features, rolling averages) -> classify_congestion.py (Random Forest)
                  -> optimize_signals.py (rule-based timing per state) -> dashboard/app.py (Streamlit)
```

## Results

Trained and evaluated on 3,360 simulated sensor readings across 5 intersections (80/20 train-test split):

| Metric | Value |
|---|---|
| Classification accuracy | **99.7%** (a re-run in Nov 2026 with scikit-learn 1.9.1 gave 99.85%) |
| Precision (weighted avg) | 1.00 |
| Recall (weighted avg) | 1.00 |
| Intervals where adaptive timing differs from a fixed 45s cycle | **72.8%** |

**Top predictive features:** vehicle count, traffic density, average speed, and rolling average vehicle count.

*Note: the labels come from rules on vehicle count and speed, so the classifier is close to perfect by construction. The value of the project is the pipeline (simulation, feature engineering, classification, adaptive timing), which is built to swap in real IoT sensor feeds. Measuring an actual congestion reduction would need a traffic simulator (e.g. SUMO) or field data.*

## How to Run

```bash
# Clone the repository
git clone https://github.com/NadavaluruSashank/Smart-Traffic-Management.git
cd Smart-Traffic-Management

# Install dependencies
pip install -r requirements.txt

# 1. Generate simulated IoT sensor data
python src/data_generator.py

# 2. Train the congestion classifier
cd src && python classify_congestion.py && cd ..

# 3. Test the signal optimizer
cd src && python optimize_signals.py && cd ..

# 4. Launch the live dashboard
streamlit run dashboard/app.py
```

## Limitations

- Simulated data with rule-based labels: the near-perfect accuracy is by construction and says nothing about real sensors.
- "72.8% of intervals differ from a fixed 45 s cycle" measures how often the recommendation changes, not a reduction in congestion. Measuring that would need a traffic simulator (e.g. SUMO) or field data.
- The signal timing engine is rule-based, not optimised or learned.

## Possible applications

Prototype for smart-city traffic analytics; the generator can be replaced with real sensor feeds.
